title: "Chapter 15: Performance Engineering"

> "AI can write logic that passes tests. It takes a Senior Engineer to write logic that passes Instruments."

When operating at scale, sub-optimal code generated by AI becomes apparent not as a crash, but as a dropped frame, a battery drain, or an out-of-memory termination. AI lacks the physical context of running on a real device. It does not know that decoding a 4K image on the main thread will cause the UI to stutter.

You are responsible for Apple-level performance. This chapter outlines the most common performance bottlenecks, how to detect them, and how to prompt the AI to fix them.

---

## 1. Memory Leaks (Retain Cycles)

### The Issue
Two objects hold strong references to each other, preventing them from ever being deallocated. In Swift, this almost always happens inside closure captures.

### Detection
- **Tools:** Xcode Instruments (Leaks, Allocations), Memory Graph Debugger.
- **Symptom:** Memory usage climbs steadily over time and never drops after closing a screen.

### The Fix Workflow
1. **Detection:** Capture a Memory Graph in Xcode and find the cycle (e.g., `ViewModel -> Task -> ViewModel`).
2. **Prompt:** *"I have a retain cycle in `ProfileViewModel.swift`. The network fetch closure is strongly capturing `self`. Rewrite this function to use `[weak self]` and safely handle the unwrapping."*
3. **Review:** Ensure the AI didn't blindly use `[unowned self]`, which causes crashes if the view is dismissed before the network call returns.

---

## 2. Main Thread Blocking

### The Issue
Heavy computations (JSON parsing, database sorting, large cryptographic hashing) executed on the main UI thread.

### Detection
- **Tools:** Xcode Time Profiler.
- **Symptom:** UI scrolling stutters (FPS drops below 60/120Hz).

### The Fix Workflow
1. **Detection:** Time Profiler shows a 500ms block on `Main Thread` originating from `parseUsers()`.
2. **Prompt:** *"The `parseUsers(data:)` function is blocking the Main Thread. Refactor this to run on a background `Task`. If it is currently synchronous, change it to `async` or use `Task.detached`. Ensure the final result is assigned to the `@Published` property on the `MainActor`."*
3. **Review:** Check that the AI actually detached the work, rather than just wrapping it in a `Task` that inherits the `MainActor` context.

---

## 3. SwiftUI Rendering & Diffing

### The Issue
SwiftUI compares the old View graph to the new View graph to decide what to redraw. If a View depends on a massive `@State` object, changing *one* property can trigger a redraw of the *entire* screen.

### Detection
- **Tools:** Instruments (SwiftUI view bodies instrument), `let _ = Self._printChanges()` inside the view body.
- **Symptom:** CPU spikes wildly when trivial UI elements (like a timer or text field) update.

### The Fix Workflow
1. **Detection:** You notice the entire `FeedView` is re-rendering every time the user types a character in the search bar.
2. **Prompt:** *"This SwiftUI `FeedView` is over-rendering. The `searchText` property is causing the entire scroll view to redraw. Extract the SearchBar into its own dedicated `View` struct and pass a `@Binding`, isolating the state updates."*
3. **Review:** Ensure the AI correctly extracted the view and didn't just wrap the text field in an `HStack`.

---

## 4. Uncanceled Asynchronous Tasks

### The Issue
When a user navigates away from a screen, any ongoing network requests or background computations should be canceled. If they aren't, you waste battery and bandwidth, and potentially crash the app when the task returns to update a deallocated view.

### Detection
- **Tools:** Network Link Conditioner, logging `deinit` blocks.
- **Symptom:** Network requests continue executing after a view is popped from the stack.

### The Fix Workflow
1. **Detection:** You notice tasks are outliving their parent views.
2. **Prompt:** *"This `async` network call inside the `onAppear` modifier is not being canceled when the view disappears. Refactor this to use the `.task { }` modifier, which automatically handles cancellation, or manually store the `Task` and cancel it in `onDisappear`."*
3. **Review:** Confirm the AI handles `CancellationError` correctly inside the `catch` block so it doesn't log false errors.

---

## 5. Image Decoding

### The Issue
Downloading a massive image and shoving it into an `Image` view forces the main thread to decode the JPEG/PNG synchronously.

### Detection
- **Tools:** Time Profiler (look for `ImageIO` frameworks on the main thread).
- **Symptom:** Massive stutters when scrolling a list of images.

### The Fix Workflow
1. **Detection:** Scrolling the feed drops frames when images appear.
2. **Prompt:** *"We are doing synchronous image decoding on the main thread in `FeedCell.swift`. Refactor this to downsample the image to exactly `100x100` points using `CGImageSourceCreateThumbnailAtIndex` on a background thread before creating the `UIImage`."*
3. **Review:** Verify the downsampling code actually runs off the main thread.

---

Performance engineering with AI is a partnership. The AI is a terrible profiler, but an excellent refactorer. Your job is to run the Instruments, find the exact bottleneck, and give the AI the highly specific prompt required to rewrite it.
