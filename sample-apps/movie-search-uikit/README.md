# 🎬 Movie Search — The UIKit MVVM-C Interview, With the Decision Log

> **Every file in this directory was generated by AI during a simulated 1-hour
> machine coding interview, from the exact prompts stored in `_prompts/`
> directories — and every architectural call made along the way is written down
> in [`DECISIONS.md`](DECISIONS.md).**

The other three sample apps cover the SwiftUI-era stack. This one answers the
interview you're statistically more likely to get: **"Our app is UIKit. Build a
movie search screen with a detail page and favorites. Use MVVM with
Coordinators. One hour."**

It also demonstrates the playbook habit the other apps only imply: keeping a
**live decision log**. In an AI-native interview, the code is cheap — what the
interviewer is actually grading is whether the architecture is *yours*. Saying
each decision out loud (and logging it) while the agent generates is how you
prove that. Each entry in `DECISIONS.md` is a mini-ADR in the same format as
the repo-level [`adrs/`](../../adrs/), ending with the sentence actually said
to the interviewer.

## Architecture

```
┌──────────────────────────────────────────────────────────┐
│                      Coordinators                         │
│      AppCoordinator ──▶ SearchCoordinator                 │
│      (own the window, create screens, do every push)      │
├──────────────────────────────────────────────────────────┤
│                         Views                             │
│  MovieSearchVC · MovieDetailVC · MovieCell · EmptyState   │
│        (bind to Box, render state, forward events)        │
├──────────────────────────────────────────────────────────┤
│                       ViewModels                          │
│   MovieSearchVM · MovieDetailVM · Box<Value> binding      │
├──────────────────────────────────────────────────────────┤
│                      Repositories                         │
│        RemoteMovieRepository · FavoritesStore             │
├──────────────────────────────────────────────────────────┤
│                        Services                           │
│        NetworkClient (actor) · ImageLoader (actor)        │
├──────────────────────────────────────────────────────────┤
│                         Models                            │
│              Movie · MovieDTO · SearchResponseDTO         │
└──────────────────────────────────────────────────────────┘
```

**The two rules that keep MVVM-C honest:**

1. `pushViewController` appears **only** inside `Coordinators/`. ViewModels
   signal intent through closures (`onMovieSelected`); coordinators turn intent
   into navigation.
2. ViewControllers are a `switch` over one exhaustive state enum
   (`SearchState`), bound through the 15-line `Box<Value>` — no Combine, no
   RxSwift (that's [Decision D3](DECISIONS.md)).

## Tech Stack

- **Swift 6** with strict concurrency
- **UIKit** (iOS 17+), fully programmatic — no storyboards, no XIBs
- **MVVM + Coordinator** (MVVM-C)
- **Diffable data sources** + compositional list layout
- **URLSession** + hand-rolled `NSCache` image loading — zero third-party dependencies
- **Swift Testing** (`@Suite` / `@Test` / `#expect`)

## Key Patterns Demonstrated

- **Coordinator memory contract** — strong children, weak parents, weak closures ([D9](DECISIONS.md))
- **Closure-box MVVM binding** without a reactive framework ([D3](DECISIONS.md))
- **Debounce + stale-response protection** as a cancellable `Task` ([D8](DECISIONS.md))
- **Async images under cell reuse** — task cancelled in `prepareForReuse`
- **Composition root DI** — every concrete type constructed in one function ([D5](DECISIONS.md))
- **Testing through protocol seams** — stub repository, isolated `UserDefaults` suite, injected `.zero` debounce

## Running

Open `Package.swift` in Xcode 16+ and build for an iOS 17 Simulator. Tests:

```bash
xcodebuild test -scheme MovieSearchUIKit \
  -destination 'platform=iOS Simulator,name=iPhone 16'
```

> ⚠️ This is a **demonstration codebase**. The API base URL is
> `api.example.com` — point `AppDependencies.live()` at a real movie API (and
> its auth) to run end-to-end. The architecture, prompts, and tests are the
> deliverable.
